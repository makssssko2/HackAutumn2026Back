# Invoice Keeper MCP

Самостоятельный MCP-сервер для Invoice Keeper. Нужен **Node.js 22.18+**. Исходники Invoice Keeper, Python, Docker и локальная база данных сотруднику не нужны: пакет обращается к работающему API через HTTPS под личной учетной записью.

**Источник:** опубликованный `invoice-keeper-mcp@1.0.0`. Этот локальный checkout добавляет OIDC; расширение ещё не опубликовано. Примеры `npx` ниже запускают прежнюю опубликованную версию с паролем. Бизнес-контракт `src/contract.json` и обработчики `src/server.mjs` сохранены побайтно.

## Корпоративный вход из этого checkout

Выполните `npm ci` в этом каталоге. В настройках IDE задайте `command: "node"`, абсолютный путь к `src/cli.mjs` в `args`, `IK_MCP_API_URL`, `IK_MCP_AUTH=oidc` и при необходимости `IK_MCP_READ_ONLY=true`. Логин, пароль и client secret не нужны. При первом запросе данных откроется браузер; завершите корпоративный вход за пять минут. Если браузер не открылся, используйте ссылку из stderr. Браузер и MCP должны работать на одном компьютере; remote/headless запуск этим способом не поддерживается. Подробности и полный JSON: [руководство MCP](../docs/mcp-guide.md).

## Подключение в IDE

Добавьте в настройки MCP IDE (формат `mcpServers`):

```json
{
  "mcpServers": {
    "invoice-keeper": {
      "command": "npx",
      "args": ["--yes", "invoice-keeper-mcp@1.0.0"],
      "env": {
        "IK_MCP_API_URL": "https://invoice.example.com",
        "IK_MCP_LOGIN": "ваш-логин",
        "IK_MCP_PASSWORD": "ваш-пароль",
        "IK_MCP_READ_ONLY": "true"
      }
    }
  }
}
```

Адрес — origin существующего API, без `/api` и других путей. Замените реквизиты на свои. Каждый сотрудник использует свою учетную запись сервиса; права `user`/`admin` проверяет API, действия входят в его обычный аудит. Версия закреплена в команде для воспроизводимого подключения. Обновление — явная замена версии в настройках.

IDE скачивает пакет и запускает его по stdio. Затем можно попросить ассистента: «Покажи мои счета в Invoice Keeper». У сервиса сохраняется общая видимость счетов согласно существующим правам API: MCP не добавляет персональное разделение по владельцу счета.

`IK_MCP_READ_ONLY=true` оставляет девять инструментов чтения. `false` также открывает бюджет и изменения состояния, но не повышает роль пользователя. Права на создание счетов и административные журналы по-прежнему требуют `admin`.

Секреты передавайте через поддерживаемое IDE хранилище секретов, переменные окружения или личный файл `--env-file`. Не сохраняйте реальные реквизиты в общий репозиторий настроек. Секреты не нужны для публикации пакета и не входят в него.

## Личный файл настроек

Вместо поля `env` в конфигурации IDE можно указать:

```json
{
  "command": "npx",
  "args": ["--yes", "invoice-keeper-mcp@1.0.0", "--env-file", "C:/Users/employee/.invoice-keeper.env"]
}
```

Содержимое личного файла:

```dotenv
IK_MCP_API_URL=https://invoice.example.com
IK_MCP_LOGIN=your-login
IK_MCP_PASSWORD=your-password
IK_MCP_READ_ONLY=true
IK_MCP_TIMEOUT_SECONDS=30
```

Без `--env-file` читается `.env.mcp` в рабочей папке запуска, если он существует. Окружение процесса имеет приоритет над файлом. Пакет не читает `.env` backend и не содержит его конфигурации. Для удаленного API требуется HTTPS; HTTP разрешен только для localhost/loopback.

## Доступные операции

15 инструментов: текущий пользователь, поиск и подробности счетов, регулярные шаблоны, сводка, бюджет, группы и каналы получателей, доставка и аудит, создание разовых/регулярных счетов, демонстрационная оплата/исправление/отмена отметки, остановка шаблона и отмена разового платежа.

Инструкции предметной области доступны через `invoicekeeper://guide`, подробности счета — `invoicekeeper://invoices/{occurrence_id}`. Prompt `review_expenses` помогает разобрать расходы за диапазон дат.

Суммы — десятичные строки; RUB, USD и EUR учитываются отдельно. Даты — `YYYY-MM-DD` в часовом поясе сервиса. `unpaid` включает просроченные счета. Ограниченные списки возвращают `possibly_truncated`; их нельзя считать полной историей. Бюджет материализует прогнозные периоды, поэтому отключен в режиме чтения.

Операции оплаты демонстрационные: реальные деньги не переводятся. Изменение оплаты требует актуальную `expected_revision`, полученную из `get_invoice`. Создание и изменение счетов могут поставить уведомления в очередь; пустой `group_ids` означает все активные настроенные каналы. Доставку выполняет обычный worker сервиса.

Сессионная cookie остается в памяти процесса; при завершении пакет пытается отозвать ее. После отзыва/истечения сессии требуется перезапуск подключения. HTTP-редиректы и автоматические повторы запросов отключены. После сетевой ошибки записи проверяйте состояние перед повтором; создание счета не идемпотентно. Ошибки не показывают тело ответа API, cookies или пароль.

## Раздача архивом

Владелец может передать сотруднику собранный файл `invoice-keeper-mcp-1.0.0.tgz`. Из любой папки:

```powershell
npx --yes "C:/Downloads/invoice-keeper-mcp-1.0.0.tgz" --env-file "C:/Users/employee/.invoice-keeper.env"
```

Это тот же самостоятельный пакет, без клонирования проекта. Для первой установки зависимостей нужен доступ к npm registry.

## Подготовка релиза

Из папки `Back/npm-mcp`:

```powershell
npm ci
npm test
npm pack --dry-run
npm pack
```

Python-адаптер и `scripts/export-contract.py`, упомянутые в исходном опубликованном README, отсутствуют в этом дереве. Контракт здесь восстановлен из опубликованного пакета и сохранён без изменений. Python не нужен для запуска npm-адаптера.

Архив содержит только `src`, этот README, пример настроек и npm metadata. В нем отсутствуют backend, frontend, `.env`, реквизиты пользователей, БД и Python-окружение. Перед публикацией выберите окончательное имя/namespace npm-пакета и обновите примеры подключения. Публикация публичного пакета размещает его код в npm; API и пользовательские данные по-прежнему требуют авторизацию. Для закрытой раздачи используйте закрытый registry или архив.

Публиковать следует только из этой папки, после входа в выбранный npm-аккаунт и согласования релиза владельцем:

```powershell
npm publish --access public
```

Здесь нет install/postinstall скриптов или сборки при установке. Используется официальный [MCP TypeScript SDK](https://ts.sdk.modelcontextprotocol.io/v2/).

самостоятельный чек: `npm test` + ожидаемый вывод: все Node-проверки проходят, exit 0.
