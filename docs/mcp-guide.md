# MCP: локальный и корпоративный вход

Руководство для сотрудника с ИИ-клиентом и разработчика адаптера. Права и правила
операций описаны в [README](../README.md#операции-и-ограничения), настройка
корпоративного провайдера — в [OIDC](oidc.md). Здесь описано текущее поведение
[npm-клиента](../npm-mcp/src/api.mjs) и [native API](../app/modules/oidc/router.py).

## MCP-STATE-001 — источник и совместимость

Статус: `current` на 2026-10-25. Каталог `npm-mcp` восстановлен из опубликованного
`invoice-keeper-mcp@1.0.0`. `src/contract.json` и `src/server.mjs` сохранены
побайтно: прежние 15 инструментов, девять в режиме чтения, ресурсы и prompt.
Изменены только вход и инструкции запуска; секреты провайдера в MCP не передаются.
Python-адаптера `mcp_server` и `requirements-mcp.lock` в текущем дереве нет.
Версия `1.0.0` в npm по-прежнему использует пароль; локальное расширение OIDC
не опубликовано и не становится доступным через прежнюю команду `npx`.

## MCP-STATE-002 — запуск корпоративного входа

Статус: `current`. Нужны Node.js 22.18+, работающий API с миграцией `0014` и
включённый администратором OIDC. Установите зависимости из `Back/npm-mcp`:

```sh
npm ci
```

В конфигурации ИИ-клиента укажите абсолютный путь своего checkout:

```json
{
  "mcpServers": {
    "invoice-keeper": {
      "command": "node",
      "args": ["/absolute/path/Back/npm-mcp/src/cli.mjs"],
      "env": {
        "IK_MCP_API_URL": "https://invoice.example.com",
        "IK_MCP_AUTH": "oidc",
        "IK_MCP_READ_ONLY": "true"
      }
    }
  }
}
```

При первом обращении к данным открывается обычный браузер. Войдите у Keycloak
или Authentik и вернитесь в ИИ-клиент. Ввод пароля и MFA происходит у провайдера.
Вход ожидается до пяти минут; параллельные инструменты используют одну попытку.
Если браузер не открылся, ссылка выводится в stderr процесса. Откройте её на том
же компьютере, где работает MCP. Удалённый SSH/headless-процесс с браузером на
другой машине не поддерживается этим loopback-сценарием.

Без `IK_MCP_AUTH` действует прежний режим `password`: обязательны `IK_MCP_LOGIN`
и `IK_MCP_PASSWORD`. Ошибка OIDC не переключает режим и не запускает повторный
вход. После отказа, отмены или истечения сессии перезапустите MCP-подключение.
`IK_MCP_TIMEOUT_SECONDS` ограничивает отдельные API-запросы, а не ожидание браузера.

## MCP-STATE-003 — границы сессии и проверки

Статус: `current`. На время входа адаптер слушает только `127.0.0.1` на случайном
порту. Callback проверяет Host, путь, метод, уникальность параметров и state.
В URL возвращается одноразовый код на две минуты; обмен требует PKCE S256 и
того же redirect URI. Сессионная cookie приходит только HTTP-ответом обмена и
остаётся в памяти MCP. Браузерный native callback не создаёт отдельную web-сессию.
После ответа, отказа, тайм-аута или остановки процесса listener закрывается.

API повторно проверяет ревизию провайдера и активность пользователя. Роли,
аудит, ограничения и срок сессии совпадают с веб-входом. При завершении MCP
пытается выполнить обычный logout; при недоступном API действует срок сессии.
Выход не завершает сессию у IdP. Обновление провайдера отзывает и незавершённые
native-входы. Автоматического повторения бизнес-запросов нет.

Проверки: [pytest](../tests/test_oidc_mcp.py) выполняет обмен с подписанным ID Token
и HTTP-имитацией IdP; [Node tests](../npm-mcp/test/oidc.test.mjs) используют настоящий
localhost listener и проверяют отмену, timeout, cookie и совместимость режима пароля.
Реальный IdP проверяйте отдельно: первый `get_current_user` → вход в браузере →
`auth_source=oidc` → `list_invoices` → завершение MCP и отзыв сессии.

самостоятельный чек: `python -m pytest -q tests/test_oidc.py tests/test_oidc_mcp.py && npm --prefix npm-mcp test` + ожидаемый вывод: все проверки проходят, exit 0; внешний IdP проверяется отдельным входом.
