# B2B API входящих счетов

B2B API по умолчанию отключён. Включайте его только после настройки `B2B_API_KEY_PEPPER`, приватного хранилища, HTTPS и явных получателей уведомлений.

## Настройка

Укажите на backend-сервере:

```dotenv
B2B_ENABLED=true
B2B_API_KEY_PEPPER=<long-random-secret>
B2B_DOCUMENT_MAX_BYTES=10485760
B2B_DOCUMENT_MAX_FILES=5
B2B_DOCUMENT_MAX_TOTAL_BYTES=31457280
```

Создайте через admin API организацию-покупателя, контрагента, доступ партнёра и проверенный банковский счёт. Выпустите отдельный ключ окружения `test` или `live`:

```http
POST /api/v1/business-partners/{partner_id}/api-keys
```

Возвращённое поле `api_key` показывается только один раз. Сохраните его в менеджере секретов партнёра. Invoice Keeper хранит только префикс и хеш секрета с pepper.

## Авторизация

Передавайте ключ только в заголовке Authorization:

```http
Authorization: Bearer b2b_<prefix>.<secret>
```

Каждый ключ привязан к одному партнёру и одному окружению. Партнёр не может передать или заменить `partner_id` и `environment` в запросе счёта. При каждом запросе проверяются scopes, срок действия, отзыв ключа и статус партнёра.

## Жизненный цикл счёта

```text
GET /api/b2b/v1/me
POST /api/b2b/v1/invoices
POST /api/b2b/v1/invoices/{id}/documents
POST /api/b2b/v1/invoices/{id}/submit
GET  /api/b2b/v1/invoices/{id}
```

JSON mutation requests and document changes require a unique `Idempotency-Key`. Every mutation carries `expected_revision`; a stale revision returns `409 revision_conflict`.

Счёт создаётся в статусе `draft`. Партнёр может редактировать его, загружать документы, отправить на проверку или отменить. Для отправки требуется чистый PDF с `document_type=invoice`. Затем внутренний администратор принимает или отклоняет счёт. Оплата фиксируется отдельной операцией администратора и никогда не может быть установлена партнёром.

Суммы передаются строками Decimal; MVP принимает только положительные суммы в RUB. После отправки финансовые поля неизменяемы. Документы приватны, хранятся под сгенерированными серверными именами и скачиваются только через авторизованный endpoint. Поддерживаются PDF, PNG и JPEG.

## Границы безопасности

- B2B bearer-ключи не авторизуют пользовательские маршруты `/api/v1/**`.
- Операции проверки и фиксации оплаты требуют существующую сессию администратора.
- Запросы партнёра всегда фильтруются по партнёру и окружению; недоступные ресурсы возвращают `404`.
- Тестовые события доставляются только тестовым получателям; рабочие получатели изолированы.
- API-ключи, содержимое документов и полные банковские реквизиты не копируются в логи или payload уведомлений.
- ClamAV можно не использовать при разработке, но перед production его следует включить. При включённом ClamAV загруженные документы остаются в ожидании до успешного сканирования.

API не создаёт обычные исходящие/демонстрационные платежи, платёжные ссылки, бюджеты или legacy-записи `Attachment`. Он ведёт отдельный реестр входящих счетов и историю аудита.
