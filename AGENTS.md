# Правила работы с Invoice Keeper

## ASYNC-REQ-001 — все операции приложения асинхронные

Статус: **required**. Источник: прямое требование владельца проекта от 2026-10-25: «все операции async должны быть». Идентификаторы правил имеют формат `<ОБЛАСТЬ>-REQ-<НОМЕР>`.

- HTTP-обработчики, операции сервисов и репозиториев с I/O, фоновые задачи и интеграции выполняются через `async def` и `await` по всей цепочке вызовов.
- Для БД используй `AsyncSession` и асинхронный драйвер; для HTTP, SMTP и сокетов — асинхронные клиенты; для файлов — асинхронный файловый API.
- Запрещено вызывать блокирующий I/O внутри async-кода, переводить обработчики в синхронный `def` или переносить целый синхронный бизнес-сценарий в threadpool вместо async-реализации.
- Чистые вычислительные помощники без I/O могут оставаться обычными функциями. Тяжелые вычисления и неизбежные синхронные вызовы сторонней библиотеки изолируй на узкой границе вне event loop; это не заменяет асинхронные БД и сетевые клиенты.
- Конкурентные задачи не разделяют одну `AsyncSession`. Ограничивай число задач, закрывай ресурсы при ошибке и отмене. Медленная SMTP-доставка не должна задерживать остальные фоновые задачи.
- При изменениях сохраняй публичные API-контракты и транзакционные гарантии. Проверяй ожидание медленного I/O, отмену и откат, а также продолжение независимых операций.

Контекст архитектуры и запуска: [README](README.md). Примеры проверок: [SMTP и worker](tests/test_async_delivery.py), [HTTP и файлы](tests/test_async_documents.py), [транзакции callbacks](tests/test_integration_callback_transactions.py).

самостоятельный чек: `python -m pytest -q tests/test_async_delivery.py tests/test_async_documents.py tests/test_integration_callback_transactions.py` + ожидаемый вывод: все тесты проходят, код завершения 0.
